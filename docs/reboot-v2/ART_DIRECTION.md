# 夜行列車：守夜協定 v2 美術規格

版本：2026-10-02／企劃稿。本文新增的是製作規格，尚未產圖、替換遊戲素材或驗收裝置效能。

## 1．這次重製要留下的感覺

車外有人影逼近，車內有剛泡好的茶、尚未收起的工具和一床厚毛毯。玩家的工作是讓這個小小的家繼續運作，好讓 A-07 能安心睡到天亮。

美術主方向定為「可居住的列車小屋」：固定直式 9：16、2D 手繪畫素插畫、狹長單點透視、暖木作與冷灰窗景。生活物件要能看出使用痕跡，危險要能在窗外辨識，功能改變要真的反映在畫面上。A-07 是原創主乘客；玩家是列車的守護系統，沒有另一個人在房間裡代替玩家走動。

參考圖中的厚毯、瓶罐、杯子、層架、工作桌、綠植與小燈，是空間氣氛與用途的參考。角色臉、衣服、物件組合、敵人外形、標誌、照片上的文字與廣告介面都重新設計。四張廣告截圖不能當成既有遊戲的玩法證據。

## 3．畫風與色彩

### 3.1 畫素語言

場景原稿為 720×1280。人物、互動物件採 360×640 的設計網格，再以 2× 放大整合；720 原稿中一個主要輪廓畫素簇通常為 2～4 px。特寫插圖可保留手繪筆觸，但不能在遊戲中混入高解析攝影材質。

輪廓以深褐或冷藍處理，避免每個物件都用純黑厚描邊。1 個設計畫素的選擇性描邊只放在角色、前景工具與會互動的關鍵剪影。木板採 3～4 階明度，玻璃採透明主體、偏青邊緣與少量暖反光；毛毯以大折面、短絨畫素簇與受壓輪廓表現，不能鋪滿均勻噪點。Dither 只用於霧、玻璃水氣與遠處陰影，不用於臉或文字。

## 4．鏡頭、尺度與畫面區域

每一車廂使用同一列車的門、窗、地板尺度，鏡頭固定在入口約 1.25 m 高，視線朝車廂末端。主消失點為畫布 `(360, 390)`，容許左右移動不超過 24 px；禁止魚眼或過廣角把傢俱拉長。中央地板／走道要形成前後距離，物件不能全貼在同一平面。

| 元素 | 720×1280 場景規格 |
| --- | --- |
| 頂部畫面緩衝 | y＝0～112；不放必讀線索 |
| 可見主要內容 | y＝112～1152 |
| 底部畫面緩衝 | y＝1152～1280；不放必點物件 |
| 主走道 | 底部寬 165～225 px，向後收至 72～96 px |
| 車門 | 寬 230～285 px；每廂門框粗細一致 |
| 後窗 | 寬 205～265 px，高 230～310 px |
| 橫向桌面 | 前景厚度 16～24 px；工具要有接觸陰影 |
| A-07 主床 | 畫面約 40～47％寬，約 34～42％高；床頭與門窗不能重疊得無法辨識 |
| 人物頭部 | 主床睡姿約 60～82 px 高；臉在最小正常畫面仍能辨識 |
| 可移動生活小物 | 原始可見剪影 36～110 px；重要操作不以小物實際畫素範圍作唯一熱區 |

整張場景採 contain 等比例呈現，不拉伸，正常觀察畫面至少保留可用高度的 60％呈現場景。較高的手機視口可把 HUD、車廂切換列與操作列放在場景外；360×640 或矮桌機視口縮排為一列狀態與一列操作，DOM 控制維持至少 44 CSS px，不能隨畫布一起縮到難以點選。必要時提供「檢視細節」聚焦某個可點物件；聚焦是可返回的檢視，不變動狀態，也不裁掉操作必須判讀的線索。

正常觀察畫面不常駐大型配電／配餐表。玩家點裝置才展開面板。展開的面板若遮住場景，遮擋區的 Canvas 熱區停止接收事件；關閉與返回固定可見。畫面下方的任務提示維持一個目標與一個動詞，詳情另開。

每個輸出包包含 `assetId`、製作版本、尺寸、色票版本、實際模型或繪製工具、來源與授權、`pivot`、`bounds`、必要遮罩、動畫 metadata、狀態對應與預覽。材質不合格的素材不能靠 UI 黑底遮掉。透明 sprite 以直通 alpha 匯出，四角透明；玻璃與霧允許半透明，不允許去背後殘留綠邊。

所有車廂共用一份幾何模板。同一物件的穩定、故障、修復狀態要保持位置、尺度、視角一致。分支升級以裝置模組替換，無須把整廂重畫成另一輛列車。檔名提案：`v2/carriages/{carriageId}/{layer}.webp`、`v2/objects/{objectId}.png`、`v2/characters/a07/atlas-{n}.png`、`v2/animation/manifest.json`。這些路徑尚未建立。

### 7.2 威脅與機構

五個動畫家族為敲窗者、攀附者、霧藤、回聲乘客、群影。每個家族 20 幀，分為接近 6 幀、接觸／動作 8 幀、退去／解除 6 幀。這是共用美術家族，不限制玩法的威脅 ID 數量。白霜、汙染與路線特有機制可由天氣、裝置及家族變體組合；沒有符合的姿勢不能只換色宣稱新敵人。

接觸動作必須有蓄勢、接觸、恢復三段。敲擊會看到肘、肩與手掌變化；攀附會看到手腳換握與重心；霧藤會改變節點彎曲與纏繞位置。`impact` 事件只通知權威遊戲狀態，不能由動畫畫面自行扣血或扣資源；揮空會播完整恢復段且不造成傷害。擊退／解除播完才回收 sprite。動作與音效、玻璃反應都依同一事件標記觸發。

每個 clip 帶有 `frames`、`fps`、`loop`、`pivot`、`duration`、`eventFrames`、`transitionTo`。相鄰幀的角色尺寸與 pivot 不漂移；不允許倒播幀數湊出恢復動作。切車廂、暫停、讀檔後不得重播已結算的命中事件。

爐火、蒸汽、收音機指標、窗外雨與遠景平移可以使用程式特效；人物、敵人肢體、門鎖與修復手段的姿勢不能用整圖位移、旋轉、縮放冒充。

## 11．可及性與效能目標

### 11.1 判讀與輸入

文字採 DOM；一般狀態文字對比目標至少 4.5：1，大字至少 3：1。美術線索不能只靠紅／綠顏色，另配形狀、位置、文字與一次清楚的狀態提示。訊號謎題的節拍、音高、方向都提供可視版本；關閉聲音能完成同一任務。

正常模式裝置名與關鍵數字至少 16 CSS px。文字放大 140％及 200％時，面板切換排版，關閉／提交／返回仍可達，不出現水平捲動。鍵盤與螢幕閱讀器能選到 15 主熱區及替代操作；焦點框由 DOM 畫出，不埋在 Canvas 中。

減少動態模式關閉列車左右晃動、視差、頻繁閃燈及非必要粒子，保留人物關鍵姿勢和任務狀態。無強制畫面震動，危險不使用連續高對比閃白。倒數與操作寬限依玩法設定，藝術效果不能縮短可反應時間。

### 11.2 出貨預算

| 專案 | 目標與量測方式 |
| --- | --- |
| 靜態場景 | 預載當前廂＋相鄰廂，其他懶載；場景來源仍為 720×1280 |
| 單圖集 | 最大 2048×2048；RGBA 解碼約 16 MiB，上線前實測解碼大小 |
| 記憶體 | 同時常駐美術解碼目標不超過 80 MiB；依裝置檔位調整常駐圖集 |
| 首次載入 | P0 第一可玩畫面美術傳輸目標 ≤6 MiB；其餘不阻塞首次操作 |
| 切車廂 | 已預載時 100 ms 內首個新廂畫面，操作不得丟失 |
| 動畫 | 畫面 render 60 Hz 目標，姿勢動畫 3～12 fps；資料判定與畫面播放分離 |
| frame time | 桌機與手機代表裝置，乾淨機況三跑中位的 p95 ≤18 ms；未量測前只標目標 |
| 降級順序 | 降粒子→降視差→降霧取樣→降姿勢播放 fps；不刪掉必讀證據，不改假姿勢 |
| 首輪裝置 | 390×844、360×640、1366×600；後續實測 iOS Safari 與 Android Chrome |

固定 frame time 守門依 `game-optimization-round` 既有要求；P0 效能超標就先修圖集、解碼、重繪範圍與特效，不用「畫素風應該很快」作證據。
